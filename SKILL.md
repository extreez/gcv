# gcv

Мета-скилл. Из ссылки на документацию сервиса делает работающий `gcv-{service}`:
CLI, MCP-сервер и скилл для агента.

## Команды

| Команда | Что делает |
|---|---|
| `/gcv add <ссылка на доки>` | Подключить новый сервис |
| `/gcv update <service>` | Обновить провайдер под изменившееся API |
| `/gcv verify <service>` | Проверить соответствие контракту |
| `/gcv list` | Какие провайдеры есть и в каком они состоянии |
| `/gcv order` | Порядок обращения к сервисам для `/creative` |

---

## Главный принцип

**Пишется только `src/provider.mjs`.** Всё остальное — механика, одинаковая у
всех сервисов, — уже написана в [templates/cli-template](templates/cli-template).
Шаблон лежит внутри этого скилла, тянуть его отдельно не нужно.

Не переписывай ядро под «особенности сервиса». Если что-то не ложится в шаблон —
сначала убедись, что это действительно про сервис. В девяти случаях из десяти
это не так.

## Каталог — кэш, а решения пользователя — нет

Это правило шаблон уже реализует, но знать его нужно: оно объясняет, почему в
`store.mjs` три файла вместо одного, и почему сводить их обратно нельзя.

| Файл | Что | Кто пишет |
|---|---|---|
| `catalog.json` | скачанное у сервиса | только `refresh`, **целиком перезаписывая** |
| `overrides.json` | модели, введённые вручную | `catalog set` / `import` / `unset` |
| `disabled.json` | модели, выключенные пользователем | `catalog disable` / `enable` |

`refresh` обязан перезаписывать свой файл целиком: всё, что пережило
перезапись, — это цена, за которую уже никто не отвечает. Но если ручные записи
лежат в том же файле, каждый `sync` молча их удаляет. Именно так и было в первой
версии `gcv-kie`: пользователь добавлял модель, которой нет в машинном источнике,
и терял её на следующем обновлении каталога, не получив ни одного предупреждения.

Отсюда:

- **Введённое человеком и выбранное человеком не смешивается со скачанным.**
  Разные файлы, разное время жизни
- Ручное значение выигрывает у скачанного — пользователь ввёл его намеренно
- Но у этого есть цена: если сервис потом начнёт публиковать эту модель сам,
  ручная запись продолжит перекрывать живые данные. Поэтому `refresh` **называет
  такие модели поимённо** и предлагает снять запись. Молча — нельзя
- Выключенная модель не удаляется, а помечается: `show` её показывает, листинги
  скрывают, `generate` и `estimate` отказываются. Проверка стоит **до** проверки
  ключа — иначе на вопрос «почему ничего не произошло» пользователь получит
  «настрой API-ключ», хотя дело не в нём

## Язык порождённых инструментов

**Любой CLI, который ты создаёшь, — англоязычный.** Справка, тексты ошибок,
заголовки таблиц, комментарии в коде. Шаблон уже такой, и ломать это не нужно:
CLI попадает к людям по всему миру, а его вывод читают и агенты.

Это касается всего, что ты дописываешь в `src/provider.mjs`: сообщения в
`GcvError`, тексты `notSupported()`, подсказки в `refreshCatalog`. Пиши их
по-английски, даже если разговор с пользователем идёт на другом языке.

**Скилл провайдера (шаг 7) — наоборот, на языке пользователя.** Он инструктирует
агента, а не пользователя. Но всё, что в нём процитировано из CLI — сообщения об
ошибках, маркеры вывода, названия колонок, — приводится по-английски и **должно
совпадать дословно**. Расхождение здесь означает, что агент будет искать в
выводе то, чего там нет.

С самим пользователем говори на его языке. Не переводятся никогда: слаги
моделей, имена и значения полей JSON, команды и флаги, коды ошибок, термины API,
пути и имена файлов.

## Как подключить новый сервис

### Шаг 1. Разведка документации

Прочитай документацию и найди ответы. Без них дальше идти нельзя:

| Вопрос | Зачем |
|---|---|
| Базовый URL и способ авторизации | `PROVIDER`, заголовки |
| Синхронный или асинхронный API? | Форма `createTask`/`getTask` |
| Эндпоинт создания задачи, форма тела | `createTask` |
| Эндпоинт статуса, какие бывают состояния | `getTask`, `STATE_MAP` |
| **В какой момент списываются деньги** | Самое важное. От этого зависит, что считать точкой невозврата |
| Возвращает ли сервис фактическую стоимость | `costActual` — или `null`, если нет |
| Эндпоинт баланса | `getBalance` |
| Нужна ли загрузка файлов для референсов | `uploadFile` или `notSupported()` |
| Есть ли машинный список моделей и цен | `refreshCatalog` |
| Умеет ли отменять задачи | `supports.cancel` |
| Как выглядят ошибки | `mapError` |

Чего не нашёл — так и запиши: `null`, `false`, `TODO уточнить`. Догадки здесь
превращаются в потерянные деньги пользователя.

#### Как искать машинный источник цен

Открытого «JSON со всеми ценами» в документации почти никогда не будет —
но это не значит, что его нет. У kie.ai он тоже нигде не документирован: страница
`kie.ai/pricing` рисует таблицу из 408 моделей, а данные под капотом дёргает
`POST api.kie.ai/client/v1/model-pricing/page` без авторизации. Нашлось это не в
доках, а в вкладке Network при открытии страницы прайсинга в браузере.

Порядок поиска для нового сервиса:

1. Открой страницу цен и страницу каталога моделей сервиса в браузере
   (`mcp__Claude_Browser__navigate` + `read_network_requests`), посмотри, какие
   XHR/fetch-запросы она делает. Прайс почти всегда подгружается отдельным
   запросом — сайт не будет вручную вписывать сотни цифр в HTML
2. Проверь, отвечает ли найденный эндпоинт без авторизации (`curl`). Если да —
   это и есть источник для `refreshCatalog`
3. Не нашёл XHR — проверь `__NEXT_DATA__`/embedded JSON прямо в HTML страницы
4. Проверь страницы отдельных моделей — иногда точный слаг и схема параметров
   лежат в OpenAPI-блоке (как у kie), а цена — на отдельной странице прайсинга.
   Это два разных источника, их придётся сводить по имени модели
5. Ничего не нашлось — `refreshCatalog` возвращает `needsManual: true`, и это
   честный результат, а не повод считать разведку проваленной

Только если все пути перебраны и источника нет — переходи к ручному вводу
(`catalog set` по документации). Ручной ввод — это план Б, а не план А.

#### Прежде чем сводить прайс с моделями по названию — поищи слаг

Прайс почти всегда говорит вывесками (`Qwen image 3.0 Pro, output, 2K`), а
документация — слагами (`qwen3/pro-text-to-image`). Соблазн свести их эвристикой
по имени велик, и она даже работает. Но **сначала проверь каждое поле строки
прайса на спрятанный идентификатор** — он там часто есть, просто не в том поле,
где ждёшь.

У kie.ai точный слаг лежит в URL-поле `anchor`, в строке запроса:

```
"modelDescription": "Qwen image 3.0 Pro, output, 2K"
"anchor": "https://kie.ai/qwen-image-3?model=qwen3%2Fpro-image-to-image"
```

Больше половины строк несут его так. Первая версия `gcv-kie` этого не заметила и
сводила всё по названиям — в итоге 78 моделей с ценой вместо 107, а у одной
картиночной модели цена бралась из строк видеомонтажа **за секунду видео** и была
завышена впятеро.

Правила, которые из этого следуют:

- Смотри на **сырой JSON** ответа целиком, а не на те поля, которые кажутся
  нужными. Слаг может быть в `anchor`, `href`, `url`, `slug`, `id`, `key`
- URL-параметры декодируй: `qwen3%2Fpro` — это `qwen3/pro`
- **Точный слаг важнее эвристики.** Нашёл его — используй и не пускай в ход
  сопоставление по имени
- Если слаг есть, но такой модели у тебя нет, — это НЕ повод откатиться на
  эвристику. Она привяжет цену к соседней модели того же семейства, и это будет
  тихая ошибка в деньгах. Честный ответ: строка не сопоставлена
- Считай и показывай, сколько строк осталось несопоставленными. Молчаливое
  «сошлось не всё» — это невидимая дыра в каталоге

### Шаг 2. Каркас

Запускается из папки скилла (`~/.claude/skills/gcv`), `--out` указывает, куда
положить готовый пакет — это папка пользователя, а не папка скилла:

```bash
node templates/scaffold.mjs --service fal --name "fal.ai" --base-url https://queue.fal.run --docs https://fal.ai/docs --api-key-url https://fal.ai/dashboard/keys --out ~/projects/gcv-fal
```

### Шаг 3. Заполнить provider.mjs

Открой `<out>/src/provider.mjs` и закрой все `// TODO` — их шесть. Интерфейс из
семи частей описан в самом файле и в [TEMPLATE.md](templates/cli-template/TEMPLATE.md).

Незыблемые правила:

- `createTask` — `retries: 0`. Автоповтор здесь означает двойную оплату
- `state` приводится к пяти значениям: `waiting`, `queuing`, `generating`,
  `success`, `fail`. Свои названия не протаскивать
- `costActual` — только если сервис реально его возвращает. Иначе `null`
- Сервис чего-то не умеет → `notSupported()`, а не эмуляция
- Все тексты, которые ты здесь пишешь, — **на английском** (см. «Язык
  порождённых инструментов» выше)

### Шаг 4. Проверить контракт

```bash
node templates/verify-contract.mjs ~/projects/gcv-fal
```

Гоняет ~80 проверок бесплатными командами: конверт `--json`, exit-коды,
предохранители, MCP, отсутствие зависимостей, незакрытые `TODO`. Реальный ключ
не нужен, деньги не тратятся.

**Пока проверка не пройдена, провайдер не готов.** `/creative` рассчитывает на
контракт, а не на добрую волю реализации.

### Шаг 5. Наполнить каталог

```bash
node ~/projects/gcv-fal/bin/gcv-fal.mjs sync
```

Если `refreshCatalog` из шага 3 реализован по источнику, найденному в разведке —
это заполнит каталог машинно, как у kie (135 моделей, 107 с ценой, курс выведен
из прайса). Не сработало — заноси модели по документации. Только те, что
реально нашёл:

```bash
node ~/projects/gcv-fal/bin/gcv-fal.mjs catalog set --model fal-ai/flux/dev --type image --credits 25 --price-unit per_image --max-refs 4 --source https://fal.ai/models/...
```

Цену не видно в документации — **оставь пустой**, не указывай флаг вообще.
Модель без цены не попадёт в план `/creative`, и это правильнее, чем фиктивная
смета. Учти: подсказка в тексте ошибки CLI выглядит как `--credits N` — это
бланк, а не разрешение подставить число по памяти.

Ручные записи ложатся в `overrides.json`, отдельно от скачанного каталога, и
`sync` их не трогает — см. «Каталог — кэш, а решения пользователя — нет» ниже.

Проверить, что получилось:

```bash
node ~/projects/gcv-fal/bin/gcv-fal.mjs models --sort price
```

```bash
node ~/projects/gcv-fal/bin/gcv-fal.mjs pick image --quality draft
```

### Шаг 6. Живая проверка

С реальным ключом, на самой дешёвой модели:

```bash
node ~/projects/gcv-fal/bin/gcv-fal.mjs doctor
```

```bash
node ~/projects/gcv-fal/bin/gcv-fal.mjs generate --model <дешёвая> --prompt "тест, синий круг" --out ./out --wait --max-cost 30
```

Это первый реальный расход — `--max-cost` обязателен. Сверь: смета совпала с
`creditsConsumed`? Разошлась — поправь каталог.

### Шаг 7. Скилл провайдера

Создай `SKILL.md` нового скилла `gcv-{service}` по образцу
[gcv-kie-skill](https://github.com/extreez/gcv-kie-skill). Скилл описывает
**особенности сервиса**, а не форму команд — команды одинаковы у всех и уже
описаны контрактом.

Что должно быть: момент списания денег, какие модели для чего, подводные камни,
таблица exit-кодов с решениями, чего не делать.

Обязательный раздел — **«Язык»**: скопируй его из образца. Без него агент будет
вываливать пользователю английские таблицы или, наоборот, переводить слаги
моделей и имена полей JSON.

Всё, что цитируешь из вывода CLI, — сверяй с реальностью, а не пиши по памяти:

```bash
node ~/projects/gcv-fal/bin/gcv-fal.mjs help
```

```bash
node ~/projects/gcv-fal/bin/gcv-fal.mjs estimate --model <модель> --count 3
```

Маркеры, названия колонок и тексты ошибок должны совпадать дословно. Это самая
частая причина, по которой скилл тихо перестаёт работать: CLI поправили, скилл —
нет, и агент ищет в выводе то, чего там больше нет.

## Иерархия сервисов

Порядок обращения задаётся в `~/.creative/settings.json`:

```json
{ "routing": { "policy": "sticky", "order": ["kie", "fal", "wavespeed"] } }
```

При `sticky` берётся первый живой из списка. Живой — это `doctor` проходит и в
каталоге есть модель нужной модальности.

`/gcv order` — показать текущий порядок и переставить.

## Обновление существующего провайдера

API сервисов меняются. Признаки, что пора:

- `verify-contract` начал падать
- Смета систематически расходится с `creditsConsumed`
- Появились ошибки `VALIDATION` на запросах, которые раньше работали

```bash
node templates/verify-contract.mjs ~/projects/gcv-fal
```

Правь `provider.mjs` и `catalog`, ядро не трогай. Если сломалось ядро — это
общая проблема, чинить в `templates/cli-template` и переносить во все пакеты.

## Когда официальный CLI или MCP уже есть

Если у сервиса есть **официальный** CLI или MCP — не дублируй его. Проверь:

- Официальный инструмент покрывает генерацию, статус, баланс и стоимость?
- Он даёт машинный вывод и стабильные коды выхода?

Оба «да» → используй официальный, а `gcv-{service}` не создавай; в
`settings.routing` пропиши его как внешний инструмент и опиши в скилле.

Хотя бы одно «нет» → создавай своего: `/creative` не сможет работать с
инструментом, который не отвечает контракту.

## Чего не делать

- Не выдумывать эндпоинты, слаги моделей и цены. Не нашёл — так и скажи
- Не подключать зависимости: и шаблон, и порождённые CLI обходятся без них
- Не отключать идемпотентность, `--max-cost` и preflight ради «простоты»
- Не объявлять провайдер готовым, пока `verify-contract` не прошёл
- Не запускать платные генерации на этапе разработки без `--max-cost`
- Не хранить ключи в коде провайдера — только через резолв из `config.mjs`
- Не сводить прайс с моделями по названию, не проверив сначала все поля строки
  на точный слаг. Эвристика по имени — последнее средство, а не первое
- Не привязывать цену «к похожей модели», когда точная не нашлась. Несопоставленная
  строка честнее неверно сопоставленной, и её видно в отчёте `sync`
- Не складывать ручные записи и выключенные модели в файл каталога: `refresh`
  перезаписывает его целиком и молча их сотрёт
