# CLI-CONTRACT v1

Единый контракт, которому обязан соответствовать **любой** `gcv-{service}` CLI.
Реализация у каждого своя и независимая — контракт общий.

`/creative` не имеет права знать ничего о сервисе сверх этого документа.

---

## 1. Имя и вызов

```
gcv-{service} <command> [args] [flags]
```

`{service}` — короткий slug в нижнем регистре: `kie`, `fal`, `wavespeed`.

---

## 2. Обязательные команды

**Настройка**

| Команда | Назначение |
|---|---|
| `init` | Мастер настройки: ключ → проверка связи → каталог. Без TTY ничего не спрашивает |
| `auth set\|show\|test\|clear` | Ключ. `show` печатает **источник и маску**, никогда — значение |
| `config get\|set\|path` | Прочие настройки |
| `doctor` | Ключ, связь, свежесть каталога, курс к USD |

**Каталог**

| Команда | Назначение |
|---|---|
| `models` | Список моделей: цена, лимиты. Фильтры `--type --search --sort --limit` |
| `prices [модель]` | Прайс: все ценовые варианты и доплаты |
| `schema <модель>` | Поля `input`, допустимые значения, обязательность |
| `pick <тип>` | Подбор модели: `--quality --budget --refs`. Несколько кандидатов с обоснованием |
| `sync` | Обновить каталог из машинных источников сервиса |
| `catalog list\|show\|refresh\|set\|import` | Низкоуровневая правка кэша |

**Генерация и деньги**

| Команда | Назначение |
|---|---|
| `estimate` | Смета без траты денег |
| `generate` | Создать задачу (и опционально дождаться). **Единственная платная команда** |
| `status` · `wait` · `download` | Работа с задачей |
| `upload <file>` | Залить файл, получить URL — если сервис требует URL для референсов |
| `cancel <taskId>` | Отмена, если поддерживается, иначе exit 9 |
| `balance` | Остаток на счету |
| `jobs` | Последние задачи: что запускалось и чем кончилось |
| `spend` | Отчёт по тратам, `--by-model` |
| `help [команда]` | Справка. Без аргумента — обзор, с аргументом — подробно с примерами |

Обязательные псевдонимы: `run`→`generate`, `credits`→`balance`, `ledger`→`spend`,
`setup`→`init`, `key`→`auth`, `recommend`→`pick`, `refresh`→`sync`.

Неподдерживаемая команда обязана существовать и возвращать **exit 9** с
`error.code = "NOT_SUPPORTED"`, а не «command not found».

Справка обязана помечать `generate` как платную команду и содержать таблицу
кодов выхода: по ней пользователь понимает, что произойдёт, до запуска.

## 3. Глобальные флаги

| Флаг | Смысл |
|---|---|
| `--json` | Машинный вывод. Обязателен для всех команд |
| `--quiet` | Только результат, без прогресса |
| `--verbose` | Диагностика в stderr |
| `--api-key <k>` | Явный ключ, высший приоритет |
| `--timeout <sec>` | Таймаут операции |
| `--no-color` | Без ANSI |
| `--yes` | Не спрашивать подтверждений |
| `--dry-run` | Всё кроме траты денег |

## 4. Конверт `--json`

Ровно один JSON-объект в **stdout**, всегда:

```json
{
  "ok": true,
  "contract": "1",
  "provider": "kie",
  "command": "generate",
  "data": { },
  "meta": { "durationMs": 4210, "apiKeySource": "env:KIE_API_KEY", "cliVersion": "0.1.0" }
}
```

Ошибка:

```json
{
  "ok": false,
  "contract": "1",
  "provider": "kie",
  "command": "generate",
  "error": {
    "code": "INSUFFICIENT_FUNDS",
    "message": "Недостаточно кредитов: нужно 50, доступно 12",
    "providerCode": "402",
    "retryable": false
  },
  "meta": { }
}
```

`error.code` — из фиксированного словаря (§6). `providerCode` — сырой код сервиса.

---

## 5. Exit-коды

| Код | Значение | `error.code` |
|---|---|---|
| 0 | Успех | — |
| 1 | Прочая ошибка | `INTERNAL` |
| 2 | Ошибка аргументов | `USAGE` |
| 3 | Нет ключа / ключ невалиден | `AUTH` |
| 4 | Не хватает средств | `INSUFFICIENT_FUNDS` |
| 5 | Ошибка провайдера (4xx/5xx) | `PROVIDER_ERROR` |
| 6 | Таймаут | `TIMEOUT` |
| 7 | Генерация упала | `JOB_FAILED` |
| 8 | Сеть недоступна | `NETWORK` |
| 9 | Не поддерживается провайдером | `NOT_SUPPORTED` |
| 10 | Превышен локальный лимит бюджета | `BUDGET_EXCEEDED` |
| 11 | Не прошла preflight-валидация | `VALIDATION` |
| 130 | Прервано пользователем | `INTERRUPTED` |

Оркестратор принимает решения **по коду выхода**, не по тексту.

## 6. Прогресс: NDJSON в stderr

При `--json` каждое событие — одна строка в **stderr**:

```
{"event":"submitted","taskId":"t_123","model":"google/nano-banana","estCredits":40}
{"event":"progress","taskId":"t_123","progress":45,"state":"generating"}
{"event":"succeeded","taskId":"t_123","creditsConsumed":40,"costTimeMs":15000}
{"event":"downloaded","taskId":"t_123","files":["out/img_1.png"]}
{"event":"failed","taskId":"t_123","code":"JOB_FAILED","message":"..."}
```

stdout остаётся чистым — там только финальный конверт.

## 7. `generate` — форма вызова

```
gcv-{service} generate
  --model <id>              обязательно
  --prompt <text>           или --input
  --input <json|@file>      сырые параметры модели, мержится поверх --prompt
  --ref <url|path>          референсная картинка; повторяемый, локальные пути
                            заливаются автоматически
  --video <url|path>        видео на входе; то же поведение
  --audio <url|path>        аудио на входе; то же поведение
  --file <field>=<url|path> файл в конкретное поле модели; повторяемый, то же
                            поведение. Три флага выше покрывают ГЛАВНЫЙ вход
                            каждого вида; всё остальное, что модель объявляет
                            (конечный кадр, маска, второй референс), адресуется
                            по имени поля из limits.inputFiles. Поля, которого у
                            модели нет, — отказ VALIDATION (код 11) до создания
                            задачи
  --count <n>               кол-во генераций (default 1)
  --out <dir>               куда скачивать. Не задано — берётся из конфига
                            (download.dir) или дефолт внутри GCV_HOME/output
  --no-download             не скачивать вовсе на этот вызов
  --wait                    ждать завершения
  --poll <sec>              интервал опроса (default 10)
  --idempotency-key <k>     защита от двойной оплаты
  --max-cost <credits|usd>  локальный предохранитель, exit 10 при превышении
```

### Скачивание по умолчанию включено

Результаты у большинства сервисов хранятся ограниченное время (у kie.ai — до
14 дней по их документации). Пропуск скачивания без явного `--out` означает
тихую потерю результата, поэтому:

- `--out` не задан, а `download.enabled` в конфиге не `false` — CLI сам
  выбирает путь (`download.dir` из конфига, иначе `GCV_HOME/output`,
  создаётся автоматически) и явно называет его в ответе (`meta.output`)
- отказаться можно только явно: `--no-download` на один вызов или
  `config set download.enabled false` навсегда — не через отсутствие пути
- файловое имя обязано включать метку времени или иной уникальный
  идентификатор: дефолтная папка плоская (без подпапки по дате), и без
  этого вторая генерация той же модели в тот же день молча перепишет файл
  первой

`data` при успехе:

```json
{
  "tasks": [{
    "taskId": "t_123",
    "model": "google/nano-banana",
    "state": "success",
    "prompt": "...",
    "input": { },
    "estCredits": 40,
    "creditsConsumed": 40,
    "estUsd": 0.02,
    "actualUsd": 0.02,
    "resultUrls": ["https://..."],
    "files": ["out/img_1.png"],
    "seed": null,
    "costTimeMs": 15000
  }],
  "totals": { "estCredits": 40, "creditsConsumed": 40, "actualUsd": 0.02 }
}
```

Если валюта сервиса — кредиты, а курс к USD неизвестен, поля `*Usd` равны `null`.
**Курс не выдумывается.**

## 8. `catalog list` — форма модели

```json
{
  "models": [{
    "id": "google/nano-banana",
    "provider": "kie",
    "type": "image",
    "modes": ["text-to-image"],
    "price": {
      "unit": "per_image",
      "credits": 4,
      "creditsMax": 4,
      "usd": 0.02,
      "usdMax": 0.02,
      "batch": 1,
      "variants": 1,
      "basis": "single",
      "inputSurcharge": null
    },
    "priceVariants": [{ "variant": null, "credits": 4, "unit": "per_image", "usd": 0.02, "kind": "output" }],
    "limits": {
      "refField": null,
      "maxRefs": null,
      "inputFiles": [],
      "maxPromptChars": 5000,
      "resolutions": null,
      "aspectRatios": ["1:1","9:16","16:9","3:4","4:3"],
      "maxDurationSec": null
    },
    "inputSchema": {
      "prompt": { "type": "string", "maxLength": 5000 },
      "aspect_ratio": { "type": "string", "enum": ["1:1","16:9"], "default": "1:1" }
    },
    "required": ["prompt"],
    "verified": true,
    "source": "https://docs.kie.ai/market/google/nano-banana",
    "fetchedAt": "2026-08-11T00:00:00Z"
  }],
  "staleness": { "fetchedAt": "...", "ttlDays": 7, "isStale": false }
}
```

### Правила цены

- **`basis: "single"`** — цена одна и точная.
- **`basis: "range"`** — цена зависит от параметров запроса (обычно разрешения).
  Тогда `credits` — нижняя граница, `creditsMax` — верхняя. Смета обязана
  показывать **обе**, а предохранители (`--max-cost`, проверка баланса) —
  считать по **верхней**. Занизить смету опаснее, чем завысить.
- **`inputSurcharge`** — отдельная плата за входные изображения, если сервис
  берёт её сверх генерации. Не смешивать с ценой генерации: иначе смета
  занижается в разы.
- **`variants`** — сколько строк прайса стоит за моделью. `priceVariants`
  раскрывает их с пометкой `kind: "output" | "input"`.
- Цена, которой нет, — `null`. **Не ноль и не догадка.**

`limits` — то, по чему `/creative` делает preflight. Поле, которого нет, — `null`,
а не выдуманное значение.

### Правила референсов

- **`refField`** — имя поля `inputSchema`, куда идут входные изображения
  (`image_urls`, `image_input`, `reference_image_urls`, `first_frame_url` — у
  каждой модели своё). `null` — модель референсы **не принимает**. Именно это
  поле, а не `maxRefs`, отвечает на вопрос «можно ли прикрепить картинку».
- **`refField` — это указатель в `inputFiles`, а не второй ответ.** Он обязан
  совпадать с именем одной из записей списка, и у этой записи всегда
  `kind: "image"` и `role: "primary"`. Указатель в пустоту — состояние, в
  которое эти два поля не имеют права попасть; оно проверяется тестом по всему
  каталогу.
- **`maxRefs`** — сколько штук максимум. `null` **при непустом `refField`**
  означает «принимает, но лимит не объявлен», а не «не принимает». Число из
  текста описания («supports up to 2 images») не парсится: догадка в лимите —
  это отказ уже после списания денег.
- `generate` кладёт `--ref` **только** в `refField`. Модель без `refField`
  получает отказ `VALIDATION` (код 11) до создания задачи: молча отправить
  референс в `image_urls` — значит оплатить генерацию, которая его проигнорирует.

### Правила файловых входов

- **`inputFiles`** — **полный** список файлов, которые модель принимает на вход,
  включая картинки:

  ```jsonc
  "inputFiles": [
    { "name": "first_frame_url", "kind": "image", "maxItems": 1, "role": "primary" },
    { "name": "last_frame_url",  "kind": "image", "maxItems": 1, "role": "end-frame" },
    { "name": "first_clip_url",  "kind": "video", "maxItems": 1, "role": null }
  ]
  ```

  Пустой список — модель не принимает файлов вовсе. Именно это поле, а не
  `modes`, отвечает на вопрос «что модель принимает на вход».
- `modes` на этот вопрос ответить **не может**, и это проверено на данных:
  `wan/2-6-video-to-video` и `topaz/video-upscale` принимают видео и числятся
  `text-to-video`, `wan/2-7-videoedit` и `happyhorse/video-edit` — тоже
  принимают видео и числятся `image-to-image`. А `wan/2-7-image-to-video`
  показывает, что деления «создание / редактирование» по режиму не существует в
  принципе: это модель создания, и она же принимает ролик для продолжения.
- **Список, а не поле на каждый тип** (`videoField`/`audioField`) — чтобы новый
  вид входа (3D, субтитры) не требовал нового поля в контракте. Одна модель
  может иметь несколько входов разом: `volcengine/video-to-video-lip-sync`
  принимает и видео, и аудио — это не взаимоисключающие случаи.
- **Картинки в списке есть, и это не дублирование.** До 0.5.0 их не было: где
  лежат картинки, решал `refField`, а второй список, повторяющий тот же ответ, —
  ровно тот способ, которым два ответа начинают расходиться. Цена этого правила
  оказалась измеримой: у **15 моделей** есть ВТОРОЙ картиночный вход (конечный
  кадр, маска, референс персонажа), и назвать его было нечем. Поэтому список
  стал полным, а `refField` перестал быть отдельным ответом и стал указателем в
  него — расходиться больше нечему.
- **`role`** — что это за вход, когда имя поля говорит об этом прямо:
  `primary` (то самое поле, куда идёт `--ref`), `mask`, `end-frame`,
  `start-frame`, `reference`. `null` — роль не распознана, и потребитель
  показывает поле под его собственным именем. Роль не выдумывается: сам факт
  наличия входа — это то, чего у потребителя не было, а название роли он
  переживёт и без нас.
- **`maxItems`** — сколько файлов помещается в поле: число, `null` («принимает
  несколько, лимит не объявлен») или `1` для одиночного URL. Те же три
  состояния, что у `maxRefs`, и тот же запрет догадываться по тексту описания.
- Вид файла (`kind`) берётся из данных схемы, а не из списка знакомых имён:
  1. **объявленные типы** — «Accepted types: video/mp4» и три других написания,
     которые kie.ai использует. Это же и **вето**: поле с `image/*` видео-входом
     не станет, как бы оно ни называлось;
  2. **имя и описание вместе** — имя вида `*_url`/`*_urls` со словом
     `clip`/`video`/`footage` (или `audio`/`voice`/`speech`/`music`) в нём, и то
     же слово в описании. Ни одного из двух сигналов в одиночку не хватает, и
     это проверено на живом каталоге: по описанию одному `image_urls` у
     `grok-imagine/image-to-video` («as a reference for video generation») и
     `input_urls` у `bytedance/seedance-1.5-pro` стали бы видео-входами, а это
     референсные картинки;
  3. **картинка** — по тем же трём сигналам, что и `refField` (объявленный тип,
     слово `image`/`photo` в имени, оно же в описании у поля-URL).
- `generate` кладёт `--video`/`--audio` **только** в поле соответствующего вида,
  а `--file <field>=<path>` — в названное поле. Поля, которого у модели нет,
  получает отказ `VALIDATION` (код 11) до создания задачи — по той же причине,
  что и с референсами: kie.ai принимает лишнее поле, списывает деньги и
  генерирует без файла.
- Имена полей отдаются **обрезанными**, и два ключа, совпадающие после обрезки,
  схлопываются в один. Две страницы kie.ai публикуют поле с пробелом на конце
  (`image_urls `, `reference_image `), а одна — обе записи разом; пробел вокруг
  ключа — это опечатка в исходнике документации, а не часть формата запроса, и
  потребитель не должен видеть фантомное второе поле.

### Расширение: точная цена вместо диапазона (опционально)

Провайдер **может** (не обязан) пытаться свести `basis: "range"` к точному
числу для конкретного запроса — по параметру входа (`--input`) или по факту
наличия референса (`--ref`), если это подтверждено схемой модели или
документированным правилом биллинга сервиса. Никогда — по догадке: ось, для
которой нет данных, просто не участвует в сужении.

Если провайдер это делает, `estimate` дополнительно возвращает:

```json
{
  "priceBasis": "exact",
  "resolvedBy": ["resolution=2K"],
  "missingFields": null
}
```

- **`priceBasis: "exact"`** — цена сведена к одному числу для этого конкретного
  запроса. `estCredits === estCreditsMax`, диапазон в смете не показывается.
- **`resolvedBy`** — какие параметры позволили сузить (для прозрачности в отчёте).
- **`missingFields`** — если сузить не удалось, но конкретное поле схемы решило
  бы вопрос: `[{"field": "resolution", "values": ["1K", "2K"]}]`. Это самый
  полезный случай отказа — оркестратор должен предложить это значение
  пользователю, а не молча показать диапазон.
- Если `basis` остался `"range"` и `missingFields` пуст — значит параметр,
  отвечающий за цену, вообще не выставляется как вход API (выбор тарифа/тира
  делается сервисом, а не запросом). Диапазон в этом случае окончательный.

Поля аддитивные (§11) — провайдер без такой логики просто не возвращает их,
`estimate` тогда работает как раньше: `basis: "single" | "range"`, без
`resolvedBy`/`missingFields`.

### Откуда берётся цена

`sync` обязан тянуть цены из машинного источника сервиса, а не из памяти модели.
Если такого источника нет, команда возвращает `needsManual: true` с подсказкой —
и каталог остаётся без цен. Смета по модели без цены не строится: `estimate`
возвращает `known: false`, а `/creative` не пускает такую модель в план.

Всё, что не удалось сопоставить, возвращается в полях `unmatched` и `failed`,
чтобы пробел был виден. Молча заполнять его запрещено.

## 9. Резолв API-ключа (порядок обязателен)

```
1. --api-key <k>
2. <project>/.env         → {SERVICE}_API_KEY
3. process.env            → {SERVICE}_API_KEY  или  GCV_{SERVICE}_API_KEY
4. ~/.gcv/config.json     → providers.{service}.apiKey
5. аргумент MCP-сервера   (только когда вызов пришёл через MCP)
```

`doctor` показывает **источник** (`env:KIE_API_KEY`, `config:~/.gcv/config.json`),
никогда — значение. В логах ключ маскируется до `sk-…abcd`.

> Риск: ключ, переданный аргументом MCP-сервера, виден в списке процессов.
> Предпочтительнее env. Оставлено как простой способ подключения — осознанно.

## 10. Побочные файлы

## 11. Правила совместимости

- `contract: "1"` в каждом ответе. Ломающее изменение → `"2"`.
- Новые поля в `data` добавлять можно, удалять — нет.
- Новые `error.code` — только с обновлением §5 и §6.
- `/creative` обязан переживать незнакомые поля молча.
